# Decisions log

One line per decision, newest last: date, decision, reason.

- 2026-09-12 — Exchange: **Binance**. Best liquidity, free spot + futures testnets, ccxt support in both languages.
- 2026-09-12 — Market: **spot first, futures later**. No liquidation risk while the bot is being proven; adapter interface keeps futures a drop-in.
- 2026-09-12 — Languages: **Python for research/backtest/signals, TypeScript for execution/dashboard/alerts**. Python has the backtesting ecosystem; you are strongest in TS for the long-running service. Shared via Postgres + Redis + JSON contracts, never cross-calls.
- 2026-09-12 — Timeframes: **default 15m entries with a 1h regime filter (S3: 5m entries, 15m range), all configurable per strategy instance** in a config file, no code change to switch. Matches how you traded; keeps trade count high enough to learn from the journal; lets the same strategy be compared across timeframes.
- 2026-09-12 — Risk: **1% per trade, 3% max daily loss**, max 3 open positions, 1 per symbol.
- 2026-09-12 — MVP: **shadow mode, no orders**. S1 support bounce on BTCUSDT; the bot marks buy points, projected sell points and follows them to an outcome in the database, with a dashboard and Telegram notifications. Paper wallet, testnet and live come only after two weeks of reviewed shadow signals. Reason: prove the bot sees what you would have seen before any money or simulated money is involved.
- 2026-09-12 — Run modes: **shadow → paper → testnet → live**, one `MODE` setting; shadow and paper share a code path, paper adds the simulated wallet.
- 2026-09-12 — Journal: **every signal is recorded, including rejected ones**, with projection at signal time and outcome written back on close. This is the dataset for judging strategies.
- 2026-09-12 — Protection: **exchange-side OCO always**; two half-size OCOs for TP1/TP2; bot only ever ratchets them. No open position without an exchange stop.
- 2026-09-12 — Migrations: **small runner inside the Python CLI** instead of dbmate; one fewer tool to install.
- 2026-09-12 — Node: **use Node 22 (or `npm i -g pnpm@9`)** because the corepack pnpm 11 shim crashes on Node 20.
- 2026-09-12 — Dashboard chart: **TradingView Lightweight Charts over our own candles**, with signals, stops, targets, trailing path and levels drawn on it; a link to TradingView for manual analysis. Binance cannot be iframed (blocks embedding), and the free TradingView widget cannot show our own markers.
- 2026-09-12 — Testing: **unit tests written with each TypeScript file as it is created** (vitest, fakes for exchange and network), same rule for Python with pytest; a step is not done with missing or red tests. Reason: order and position logic is where bugs cost money, and retrofitting tests never happens.
- 2026-09-12 — Ports: **Postgres on host 5435, Redis on host 6375** (compose maps to container defaults) because other local projects already use 5432 and 6379.
- 2026-09-12 — Dropped `pandas-ta` (needs Python 3.12); indicators are implemented in-house in `research/indicators.py`, which also makes the TypeScript port straightforward.
- 2026-09-12 — M2 verdict for S1 v1: **not good enough, proceed to shadow anyway**. Full-history backtest (2023-01 → 2026-09, BTCUSDT 15m/1h, 0.1% fee, 0.05% slippage): 60 trades, 36% win rate, expectancy −0.40R; walk-forward out-of-sample (180d train / 60d test, 32-combo grid): 41 trades, −0.35R. Beats the random baseline (−0.58R) but loses. Fees exceed the loss in both runs, so stops are too tight relative to a 0.2% round trip; 22 of 60 exits were the regime rule. Shadow mode (M3) validates the pipeline while S1 iterates: widen stops or use ATR-based stops, soften the regime exit, consider the BNB fee discount (0.075%), then re-run the walk-forward.
- 2026-09-12 — Spot sizing reality: **effective risk per trade = min(risk_pct, notional_cap_pct × stop distance)**. A 1% risk target with a 0.9% stop needs 114% of equity in notional; the 25% cap makes the real risk about 0.22%. The risk manager reports the capped amount and the journal records it. To trade 1% real risk on spot, stops need to be ≥ 4% of price or the cap must rise.
- 2026-09-12 — Enums in TypeScript keep **string values wherever they cross a boundary** (journal columns, Redis events, Python fixtures); numeric defaults only for enums that never leave the process.
- 2026-09-12 — Live regime invalidation closes at the regime candle's close price; the backtester closes at the next entry-bar open. The difference is one 15m gap and is accepted for shadow; paper mode (M5) will fill at next open to match the backtester exactly.
- 2026-09-12 — Shadow soak diagnosis: hours without a signal is expected. Every evaluation so far was blocked by the 1h regime filter (all ten symbols below EMA50 < EMA200); a 30-day replay of all ten S1 instances yields 5 signals total (~1 per 6 days across the basket). Loosening `wick_min_pct` / `rsi_max` or the `close > EMA50` half of the trend gate is strategy iteration, not a bug, and changes what the shadow-vs-backtest comparison measures.
- 2026-09-12 — Paper mode (M5): the entry is **pending until the next entry-timeframe candle**, fills at that open plus slippage, is sized at that open (step-rounded, minimums checked), and `risk_amount = (fill − stop) × qty`, so `pnl == r_multiple × risk_amount` holds exactly and `research compare --mode paper` can demand R equality with the backtester. A fill beyond the stop or target cancels the entry (`gap_at_fill`), as in the backtester. Exit fills go through the adapter too, so the wallet sees every sell.
- 2026-09-12 — Equity snapshot semantics: `balance_quote` = cash + cost of open positions, `unrealised` = Σ remaining_qty × (mark − entry); equity = sum of both; drawdown from the running peak. Sizing uses cash + open cost.
- 2026-09-12 — Several engines, one journal: consumer groups are per mode (`engine:<mode>`) so a paper engine can run beside the shadow soak and see every signal and command; the **first mode to act on a signal owns its outcome columns** (`WHERE mode IS NULL OR mode = current`), every mode's own outcomes live in `positions`, and risk history (daily R, consecutive losses) is read from `positions`, not `signals`.
- 2026-09-12 — Exit params `trail_atr_k: null` / `tp_ratchet_atr: null` mean "off" in both exit-policy implementations and the signal contract (needed by S3, mean reversion).
- 2026-09-12 — Backtester look-ahead fix: regime invalidation was evaluated at bar i's open when the regime bar closed together with bar i; it now acts one entry bar later (`regime_idx[i-1] != regime_idx[i-2]`), the first bar at which that close was known. S1 backtest numbers shift slightly; the would-have-won replay uses the same rule.
- 2026-09-12 — S3 "range breaking" exit is the price proxy `invalidation_level = range_low` (regime-tf close below the range low), not the plan's 1h ADX > 25: the engine's invalidation is price-based and needs no indicator code. S3 keeps `max_fee_r` at 0.5 (S1/S2: 0.25) because its stop sits just under the range low.
- 2026-09-12 — Binance protection (M6): two sell OCOs (A: tp1 / stop on the TP1 fraction, B: tp / stop on the rest), stop-limit 0.2% under the stop, replaced only when the stop rose ≥ 1 tick and 0.05%, the target changed or the quantity changed, at most once per candle. OCO rejected because the market is already through the stop or target → that quantity is sold at market and alerted; rejected for another reason → a lone stop-loss-limit (upgraded to an OCO next candle); three failed placements → the whole position is sold at market (`order_rejected`) and force-closed. Exits decided by the exit policy first consume fills the exchange already made, then cancel and sell the remainder at market.
- 2026-09-12 — Live gate (M7): `engine_state.entries_enabled` defaults to **false** for `mode = live` and true elsewhere; a live engine boots as a dry run (balances, filters, user stream, reconciliation) and is armed with the `entries_on` command from the Controls page. Testnet keys are separate env vars (`BINANCE_TESTNET_API_KEY/SECRET`); the mode can be overridden per process with `MODE=` so engines of different modes can share one config file.
- 2026-09-12 — Reconciliation policy: an open order on the account that we did not place pauses new entries (it is never cancelled — it may be yours); a position without an exchange stop is re-protected on the spot; a base balance below what positions hold raises `reconcile_mismatch` without pausing.
- 2026-09-13 — Historical data: 14 coins × 15m/30m/1h/2h/4h/1d backfilled from 2021-04-01 (or listing date) from Binance spot; `SHIBUSDT` replaces the futures-only `1000SHIBUSDT`. Only gaps are Binance-wide outages (12 hours in total). Reason: five years covering a bull run, a bear market and ranges, so walk-forward results are not one regime's luck.
- 2026-09-13 — Symbol universe: **not** every USDT pair. The median Binance USDT pair trades $0.4M/day at a 0.15% spread, a ~−0.3R handicap per trade before the strategy acts. `research universe` keeps the 14 pinned coins plus every pair with a 30-day average volume > $10M and spread < 0.05% (~30 coins), each with a copy of `s1_btc_15m`, in an auto-generated block of `strategies.yaml`; refreshed weekly by the `universe-refresh` pm2 cron job, non-pinned coins drop out when they fall below the bar.
